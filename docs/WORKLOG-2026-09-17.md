### 2. `EditorViewModel.load()` 레이스 컨디션 수정 (실제 버그, 확인됨)
탭을 빠르게 전환하면 이전 노트 내용이 잠깐 보였다 사라지는 현상의 원인이었다.
SwiftUI `.task(id:)`가 취소한 이전 로드 작업이 `await` 재개 후에도 계속 실행되며
새로 로드된 상태를 덮어쓰고 있었다. `await` 지점마다 `guard !Task.isCancelled else { return }`를
추가해서 해결했다. `EditorView.swift`의 바깥 `.task(id: noteID)` 블록에도 동일한 가드를 추가했다.

### 4. "탭 클릭이 안 먹는다" 버그 — 근본 원인 격리 시도 (미해결)
현상: 패키징된 `.app`에서만 탭 클릭이 반응하지 않음. `swift build`로 만든 원시 디버그
바이너리에서는 100% 재현되지 않음.

다음 변수들을 하나씩 바꿔가며 제외했으나 **정확한 원인은 끝내 특정하지 못함**:

| 변수 | 테스트 결과 |
|---|---|
| Whole-module vs singlefile 컴파일 | 원인 아님 |
| `-O` vs `-Onone` 최적화 | 원인 아님 |
| App Sandbox 켬/끔 | 원인 아님 |
| Debug vs Release 설정 | 원인 아님 (Debug 아카이브도 동일하게 실패) |
| `open` vs 실행 파일 직접 실행 | 여전히 실패 |

남은 미검증 변수: Hardened Runtime 단독 비활성화, `.app` 번들 자체(Info.plist/리소스 포함) 여부.
현재는 이 조사를 잠시 중단하고, 지금까지 확인된 것 중 가장 안정적이었던 설정
(`SWIFT_COMPILATION_MODE: singlefile` + `SWIFT_OPTIMIZATION_LEVEL: -Onone`)으로
릴리즈를 우선 배포하기로 결정.

### 5. 릴리즈 설정 정리
- `NotepadX.entitlements`의 `com.apple.security.app-sandbox`를 진단용 `false`에서
  원래 값인 `true`로 되돌림 (샌드박스는 버그 원인이 아님이 확인되었으므로 정상적인
  보안 설정으로 복귀)
- `project.yml`의 Release 설정(`singlefile` + `-Onone`)은 유지 — 마지막으로 정상
  동작이 확인된 조합이기 때문
- `xcode-select`가 Command Line Tools를 가리키고 있어 아카이브 빌드가 실패했던 것을
  발견 → 사용자가 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
  실행 후 해결
- 버전을 1.1.0 → **1.2.0** (`CFBundleVersion` 2 → 3)으로 올림
